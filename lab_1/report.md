## Базовий сценарій

За допомогою облікового запису `standard_user` було перевірено авторизацію, перегляд каталогу, сортування товарів, додавання товару до кошика та оформлення замовлення.
Основний сценарій було завершено успішно, відхилень у роботі не зафіксовано.

## Порівняльне тестування облікових записів

| Обліковий запис | Спостереження |
|-----------------|---------------|
| `error_user` | Під час вибору будь-якого варіанта сортування на сторінці Products з'являється повідомлення "Sorting is broken! This error has been reported to Backtrace.", порядок товарів не змінюється |
| `locked_out_user` | Вхід неможливий: система не пускає користувача в застосунок. Така поведінка відповідає призначенню заблокованого облікового запису, тому дефектом не вважається |
| `visual_user` | Ціни на сторінці Products змінюються після кожного оновлення сторінки або переходу через All Items, тоді як в картці товару та в Cart відображається стабільна ціна |
| `standard_user` | Еталонний профіль: сценарій проходить повністю, ціни стабільні, сортування працює коректно |
| `performance_glitch_user` | Перехід до сторінки Products після авторизації відбувається помітно довше, ніж у `standard_user` |

## Висновок

У ході роботи пройдено базовий сценарій SauceDemo під обліковим записом `standard_user` і взято його поведінку за еталон для порівняння. Перевірка інших тестових профілів виявила три відхилення: сповільнений перехід до Products для `performance_glitch_user`, нестабільні ціни в каталозі для `visual_user` та помилку під час сортування для `error_user`. Після зіставлення Expected Result і Actual Result кожну аномалію підтверджено як дефект і оформлено окремим GitHub Issue із середовищем, кроками відтворення, Severity та Priority. Відмову у вході для `locked_out_user` дефектом не визнано, бо обліковий запис заблоковано за задумом. Жоден із виявлених дефектів не блокує оформлення замовлення.
